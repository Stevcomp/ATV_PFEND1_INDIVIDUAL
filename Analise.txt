ANÁLISE DO PROJETO — DEVRESOURCES MANAGER

PROPOSTA

- Objetivo: organizar um catálogo local de ferramentas úteis para desenvolvimento web.
- Usuário principal: pessoa desenvolvedora que consulta e mantém referências de ferramentas.
- Registro gerenciado: ferramenta, com nome, categoria, tipo, descrição e link.
- Escopo: um tipo principal de registro. A API guarda os dados em memória, que são apagados quando ela reinicia.

COMO AS PARTES SE RELACIONAM

O navegador mostra as páginas do Next.js. As páginas usam fetch para enviar e receber dados da API Express. No back-end, as rotas encaminham cada pedido ao controller; o controller chama o service, que valida e aplica as regras usando o model. O model guarda os registros no array em memória.

GUIA DE ESTUDO — COMO O FRONT-END FUNCIONA

1. COMO O NEXT.JS ORGANIZA AS PÁGINAS

O front-end usa o App Router do Next.js. Os arquivos page.jsx definem as páginas conforme as pastas em frontend/src/app:

- frontend/src/app/page.jsx corresponde à página inicial, no endereço /.
- frontend/src/app/ferramentas/nova/page.jsx corresponde ao cadastro, em /ferramentas/nova.
- frontend/src/app/ferramentas/editar/[id]/page.jsx corresponde à edição. O trecho [id] é dinâmico; por exemplo, /ferramentas/editar/3 abre a ferramenta de ID 3.

O layout.jsx envolve essas páginas. Ele carrega o Bootstrap e o CSS global, mostra o Header, coloca o conteúdo da página dentro de main e exibe o rodapé. Por isso o cabeçalho e o rodapé aparecem em todas as páginas.

O Header é o cabeçalho reutilizado: o nome do sistema leva à página inicial e o botão Cadastrar ferramenta leva ao formulário de cadastro. O layout também define o título e a descrição usados como metadados da página.

2. COMO O FRONT-END SE COMUNICA COM A API

O endereço padrão é http://localhost:3001/api. Se frontend/.env definir NEXT_PUBLIC_API_URL, esse valor substitui o padrão. Em FormFerramenta/index.jsx, API_FERRAMENTAS combina o endereço da API com /ferramentas.

A função chamarApi, também exportada por FormFerramenta/index.jsx, recebe um endereço e opções do fetch. Ela envia a requisição, confirma que a resposta é JSON, transforma o JSON em um objeto JavaScript e verifica se o servidor respondeu com sucesso. Se houver falha HTTP, lança um erro com a mensagem enviada pela API e guarda o status HTTP no erro. Se não houver conexão, o fetch também gera um erro, tratado pela página ou pelo formulário.

As respostas bem-sucedidas da API têm os dados dentro da propriedade dados. Por exemplo, a listagem lê resultado.dados. Os pedidos enviados pelo formulário usam JSON e informam o cabeçalho Content-Type: application/json.

3. PÁGINA INICIAL — LISTAR, BUSCAR E EXCLUIR

Ao abrir /, page.jsx cria estados para a lista de ferramentas, o texto de busca, o carregamento, os erros e as mensagens de sucesso. O uso de useState permite que a tela seja atualizada quando esses valores mudam.

O useEffect é executado quando a página é carregada. Ele lê o parâmetro mensagem da URL para mostrar uma confirmação após cadastro ou edição. Depois remove esse parâmetro do endereço com history.replaceState. No mesmo efeito, faz GET /api/ferramentas usando chamarApi e guarda a lista recebida em ferramentas. Enquanto espera, mostra a mensagem de carregamento; se ocorrer um erro, mostra uma mensagem de falha.

A busca é feita no próprio navegador, sem novo pedido à API. O código combina nome, categoria, tipo e descrição de cada ferramenta, converte o texto e a busca para minúsculas e mantém os registros que contêm o termo digitado.

Para cada resultado, a página cria um CardFerramenta. O cartão apresenta categoria, nome, tipo e descrição. Seu link externo abre o endereço da ferramenta; o botão Editar leva à página do ID correspondente; o botão Excluir chama a função excluirFerramenta da página inicial.

Ao excluir, a página pede confirmação com window.confirm. Se o usuário confirmar, envia DELETE /api/ferramentas/:id. Quando a API confirma a exclusão, o registro é removido do estado local com filter, sem recarregar toda a lista, e uma mensagem de sucesso aparece. Se a operação falhar, a mensagem de erro é exibida.

4. CADASTRO — CRIAR UMA FERRAMENTA

A página /ferramentas/nova mostra o formulário compartilhado FormFerramenta. A página fornece a função salvar como propriedade onSubmit e o texto Cadastrar para o botão.

Ao enviar o formulário, salvar transforma os dados em JSON e chama POST /api/ferramentas. Se a API aceitar os dados, useRouter navega de volta para /. O endereço leva mensagem=cadastrada, que a página inicial lê e apresenta como confirmação.

5. FORMULÁRIO COMPARTILHADO

FormFerramenta é usado tanto no cadastro quanto na edição. A propriedade valores permite preencher os campos com dados existentes; sem ela, o formulário começa vazio. A propriedade onSubmit informa à página que o utiliza o que fazer com os dados. textoBotao define o texto do botão principal.

O estado form guarda o conteúdo atual dos campos. A função alterar usa o atributo name do campo editado para atualizar apenas aquele valor. Os campos required, type=url e maxLength fornecem validações básicas do navegador; o back-end também valida os dados antes de armazená-los.

Quando o formulário é enviado, enviar impede o comportamento padrão do navegador, limpa o erro anterior, ativa o estado salvando e chama onSubmit(form). Se houver falha, mostra a mensagem no formulário e libera o botão novamente. Durante o envio, o botão fica desativado e exibe Salvando.... O link Cancelar volta ao catálogo sem enviar dados.

6. EDIÇÃO — BUSCAR E ATUALIZAR

A página /ferramentas/editar/[id] usa useParams para obter o ID da URL. Seus estados guardam os dados carregados, o indicador de carregamento e uma possível mensagem de erro.

O useEffect executa GET /api/ferramentas/:id para buscar a ferramenta. Enquanto espera, a página mostra Carregando ferramenta.... Se o ID não existir, a API responde 404 e a página explica que os registros ficam em memória e se perdem quando o back-end reinicia. Quando os dados chegam, a página passa a ferramenta para FormFerramenta pela propriedade valores.

Ao enviar alterações, a função salvar envia PUT /api/ferramentas/:id com os novos dados em JSON. Se a API responder com sucesso, a página volta a /?mensagem=atualizada e o catálogo mostra a confirmação.

7. FLUXO COMPLETO DE UM CADASTRO

Usuário preenche FormFerramenta → página nova envia POST → rota Express encaminha ao controller → service valida os dados → model armazena a ferramenta → API devolve JSON → front-end navega ao catálogo → página inicial busca e mostra a lista atualizada.

8. FLUXO COMPLETO DE UMA EDIÇÃO OU EXCLUSÃO

Edição: cartão abre /ferramentas/editar/:id → página busca GET /api/ferramentas/:id → formulário mostra os dados → envio faz PUT → a API atualiza o registro → navegador volta ao catálogo.

Exclusão: cartão chama a função da página inicial → usuário confirma → front-end envia DELETE → API remove o registro → front-end retira o cartão da lista e mostra confirmação.

9. O QUE A INTERFACE NÃO FAZ

O front-end não acessa o array de ferramentas diretamente. Ele só envia pedidos HTTP e mostra as respostas da API. O array fica no back-end; por isso, reiniciar a API apaga os registros atuais. O globals.css controla a aparência e a adaptação a telas menores, mas não participa da comunicação com a API.

10. RESUMO DAS ROTAS DA API USADAS PELO FRONT-END

- GET /api/ferramentas — carrega o catálogo na página inicial.
- GET /api/ferramentas/:id — carrega os dados antes de editar.
- POST /api/ferramentas — cadastra uma ferramenta.
- PUT /api/ferramentas/:id — salva as alterações de uma ferramenta.
- DELETE /api/ferramentas/:id — exclui uma ferramenta após confirmação.

As páginas usam o prefixo API_FERRAMENTAS, definido a partir do endereço configurado, e acrescentam o ID quando a operação é específica de uma ferramenta.
